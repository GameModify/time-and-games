# Интеграция Activity Tracker

Activity Tracker находится в отдельном репозитории и работает отдельным процессом. Time & Games не запускает его, не читает его SQLite и не импортирует его исходники. Контракт: HTTP API v1, проверяемый Zod-моделями в src/shared/api/trackingContracts.ts.

## Подключение

1. Запусти Activity Tracker отдельно. Стандартный адрес http://127.0.0.1:3536.
2. Открой Настройки → Автоматический учёт, укажи ключ read из data/credentials.json трекера и включи подключение.
3. Добавь соответствия меток его правил категориям сайта. Например coding → Кодинг, projects → Проекты, video → YouTube / Видео.
4. Проверь полученные интервалы. Автоимпорт включается отдельным чекбоксом и затрагивает только завершённые интервалы с известной категорией.

Отключение подключения прекращает синхронизацию сайта. Кнопка приостановки обращается к сервису и останавливает сам сбор. Сайт сохраняет самостоятельный запуск при обоих вариантах. Расширение Chrome устанавливается из репозитория трекера.

## Модули и данные

- server/tracking/http.ts: HTTP-адаптер, разрешён только literal loopback 127.0.0.1 без userinfo, query, hash и дополнительных путей; redirect запрещён.
- server/tracking/storage.ts: настройки и очередь в базе сайта; JSON ограничен SQLite-границей.
- server/tracking/controller.ts: ограниченная постраничная синхронизация каждые 15 секунд, обработка недоступности, смены устройства и автоматического импорта.
- server/tracking/import.ts: вычитание уже учтённых интервалов категории и транзакционное принятие записи.
- pages/settings: форма подключения, соответствия, редактор правил и очередь проверки. Используются общие CheckboxField и элементы формы.

Cursor сохраняется одной транзакцией со страницей данных. Устройство и interval id образуют ключ идемпотентности. Принятый или пропущенный интервал сохраняет отметку обработки, даже если сессия отредактирована или удалена вручную. Исходные поля уже обработанного интервала не перезаписываются повторной синхронизацией. При смене device_id cursor сбрасывается.

В импорт попадают только положительные завершённые интервалы. Существующие ручные и автоматические интервалы выбранной категории вычитаются; разные категории могут пересекаться по правилам общей статистики. Для неопознанных занятий категория выбирается вручную. Изменение правила трекера влияет на его новые интервалы.

Настройки подключения, ключи и очередь не входят в формат резервной копии библиотеки. Восстановленные сессии считаются существующим временем при следующем импорте. Сброс сайта отключает подключение и очищает очередь; отдельная база трекера остаётся под управлением трекера.

## Разделение репозиториев

Трекер выбран отдельным продуктом со своим хранением, тестами, CI и версионированным API. Сайт выступает клиентом. Расширение Chrome живёт вместе с сервисом как сборщик; новые клиенты могут использовать тот же API. Разделение проверяется независимой установкой зависимостей, сборкой и запуском без соседнего checkout.

Monorepo также допускает независимые приложения; это не равно общему процессу. Для данной системы отдельные репозитории явно закрепляют владение данными и релизами. [Описание различий](https://nx.dev/docs/kb/what-is-a-monorepo), [рекомендации о границах и данных сервисов](https://learn.microsoft.com/en-us/azure/architecture/guide/architecture-styles/microservices).
## Категории контента

В «Записях и результатах» у завершённого отрезка есть действие «Категория». Можно исправить только запись, назначить проект или сохранить правило для известного видео, канала, сайта либо приложения. Предварительный просмотр объясняет область действия. Изменение одной записи не требует доступного трекера; перед сохранением будущего правила проверяется связь, при её ошибке запись не меняется. Остальная история сохраняется.

Категории публикуются в нейтральный каталог трекера. Метки tng:<ID> разрешаются в категорию клиента; прежние mappings передаются как псевдонимы. Каталог обновляется при синхронизации. YouTube без отдельного правила попадает в имеющуюся категорию просмотра YouTube. Видео и канал сохраняются в tracking_context, включая резервные копии.

Расширение показывает выбор категории рядом с подпиской в настольном YouTube. Точное видео важнее канала, сброс отдельного правила возвращает наследование. Ключи остаются в фоне расширения. Используется существующее разрешение на сбор YouTube. При сохранении из сайта применяется If-Match существующего API правил: конкурентное изменение вызывает повторное чтение и слияние, а не потерю соседних правил.
