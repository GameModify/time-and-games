# Архитектура Vue

Решение проверено по официальной документации **23 октября 2026 года**.

Проект использует Vue 3, Composition API и `<script setup lang="ts">`, с декомпозицией по принципу **pages first из FSD 2.1**. Сначала выделяем самостоятельные экраны, затем выносим действительно общие сценарии и предметную логику. Не создаём пустые слои и по отдельному модулю для каждой кнопки.

## Структура

```text
src/
  app/
    App.vue                     # каркас, навигация, сборка моделей
    config/navigation.ts
    config/router.ts            # Vue Router и обычные URL
    styles/base.css             # размеры, сетки, компоненты
    styles/themes.css           # семантические цвета и светлая палитра
  pages/
    activity/                   # таймлайн и статистика общего периода
    games/                      # библиотека и локальная модель фильтров
    media/                      # фильмы, сериалы, каталог и редактор прогресса
    settings/                   # категории, оформление, резервные копии
  features/
    workspace/                  # загрузка общей базы, диапазон дат, таймеры
    record-editor/              # редактирование, удаление, импорт и диалоги
    appearance/                 # смена и сохранение темы
  entities/
    activity/                   # объединение интервалов, аналитика, колонки таймлайна
    game/                       # статусы игр
    media/                      # статусы просмотра, серии и расчёт времени
  shared/
    api/client.ts               # HTTP и единая обработка ответов
    api/contracts.ts            # Zod-схемы и выводимые типы API
    api/mediaContracts.ts       # контракты киноколлекции и каталога
    ui/RatingInput.vue          # звёздная оценка с шагом 0,5
    ui/SearchField.vue          # единый поиск с иконкой и рамкой фокуса
    ui/CheckboxField.vue        # чекбокс с переносимой подписью
    lib/navigationState.ts      # проверка и сохранение навигации в URL
    lib/date.ts                 # локальные даты и общая арифметика времени
    lib/format.ts               # форматирование для UI
  main.ts                       # точка входа
```

## Границы

Зависимости направлены вниз: `app → pages → features → entities → shared`. Можно пропускать слои. Страница не импортирует другую страницу, feature — другую feature. Внешние импорты срезов идут через `index.ts`; детали реализации остаются внутри. Проверка `scripts/check-architecture.ts` включена в `npm run check` и CI.

`App.vue` создаёт модели один раз. Страницы получают необходимые модели и действия явными props; не импортируют состояние из `app`. Модель редактирования получает зависимости аргументом. Это позволяет менять каркас приложения и проверять расчёты без браузера. Публичный результат composables содержит refs и обработчики, сохраняющие реактивность при деструктуризации; `reactive` применяется на границе передачи модели в UI. Внутри крупных моделей используются контроллеры с явными зависимостями и стрелочными обработчиками, которые сохраняют контекст при передаче в компоненты. Это локальные владельцы состояния Composition API; методы загрузки, проверки и сохранения разделены по назначению.

Состояние фильтров принадлежит библиотеке игр. Состояние формы принадлежит редактору. Общее состояние таймеров и выбранного периода живёт в единственном экземпляре модели рабочего пространства. Интервалы и обработчики очищаются при размонтировании.

Pinia — официальная рекомендация Vue для более сложного управления общим состоянием. Здесь пока достаточно одного владельца состояния и composables, без глобальных singleton и дополнительных зависимостей. При появлении независимых маршрутов, нескольких владельцев состояния или необходимости DevTools stores можно заменить внутреннюю реализацию модели на Pinia, сохранив границы модулей. Vuex для нового кода не используется.

## Навигация

Vue Router использует `createWebHistory`: `/` для дневника, `/games` для игр, `/media` для фильмов и сериалов, `/statistics` для статистики и `/settings` для настроек. `RouterView` отображает страницу, а общие модели живут в `App.vue`, поэтому переходы не перезапускают таймеры.

В query остаются только нестандартные параметры календаря: выбранная дата, неделя/месяц и режим списка. У настроек и библиотеки этих параметров нет. Старые `#page=...` ссылки переводятся на соответствующий новый адрес. История браузера и обновление страницы сохраняют выбранный экран. Express отдаёт `index.html` для прямого открытия клиентских маршрутов; API обрабатывается отдельно.

## TypeScript

`vue-tsc` проверяет весь проект, включая Vue-шаблоны, сервер, конфигурацию, скрипты и тесты. Включены `strict`, `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns` и `noFallthroughCasesInSwitch`. ESLint использует `strictTypeChecked`, проверяет промисы и требует type-only imports. Предупреждения запрещены в CI. Prettier отвечает за форматирование.

Общие контракты API выводятся из Zod-схем в `shared/api/contracts.ts`; входные запросы сервера и ответы Steam проходят отдельные схемы. JSON сначала рассматривается как `unknown`, затем проверяется. Формы используют отдельные типы для редактируемых значений, включая пустые числовые поля.

Функции, методы и callback ограничены 20 строками, включая сигнатуру, пустые строки и комментарии. Когнитивная сложность не превышает 20. Правила `max-lines-per-function` и `sonarjs/cognitive-complexity` действуют также в тестах и скриптах без исключений.

Входные DTO находятся в `shared/api/inputContracts.ts`. `readApi` возвращает проверенную модель, `api` выполняет запись без передачи непроверенного ответа в UI. JSON разбирается только в адаптерах HTTP, SQLite и резервных копий, что закреплено ESLint. `server/storage.ts` проверяет строки SQLite схемами; модули игр, категорий, сессий и резервных копий работают с моделями. Импорт выполняется транзакционно.

Node.js 24.12+ выполняет сервер, тесты и скрипты непосредственно из `.ts`. Используем erasable-синтаксис и явные расширения `.ts`, без enum и parameter properties. Проверка типов выполняется отдельно, до сборки и в CI.

## Киноколлекция

`pages/media` владеет фильтрами, формой и поиском. `entities/media` содержит чистые функции перехода между сериями и оценки времени; их использует также сервер. `RatingInput` в shared используется редакторами игр и киноколлекции, поддерживает клавиатуру и значения от 0,5 до 10.

`server/media.ts` изолирует хранение и HTTP-маршруты. Таблица SQLite `media` создаётся при запуске; уникальный IMDb ID предотвращает дубликаты. `server/media-catalog.ts` обращается только к фиксированному HTTPS-хосту Cinemeta, проверяет внешние ответы и кэширует их на час с ограничением размера и времени запроса. Ключ каталога не требуется. При недоступном каталоге остаётся ручной ввод.

Просмотренное время не создаёт сессий: оно хранится в карточке отдельно от дневной статистики. При расчёте используются длительности просмотренных серий, затем средний хронометраж; неизвестная длительность не подменяется вымышленной. Ручное время сохраняется при изменении прогресса. Общедоступный рейтинг IMDb и личная оценка хранятся раздельно, отправки оценок в IMDb нет.

`server/media-titles.ts` дополняет результаты русскими названиями Wikidata по IMDb ID, одним пакетным запросом до 24 названий. Переводы и отсутствующие названия кэшируются на сутки (до 1000 записей), одновременные одинаковые запросы объединяются. Таймаут 2,5 секунды и пауза после ошибки позволяют сохранить поиск на оригинальном языке при сбое перевода.

Избранное хранится в SQLite (`games.favorite`) и JSON-карточке (`media.favorite`), входит в резервные копии. Столбец добавляется идемпотентно при запуске, старые копии и карточки получают `false`. Компоненты `FavoriteButton` и `FavoriteFilter` переиспользуются обеими библиотеками. Игровые фильтры статуса, избранного и дат независимы; общий `dateInPeriod` проверяет выбранную дату начала или завершения.

`pages/activity/lib/libraryHistory.ts` строит сводку и помесячные группы из библиотек. Завершения учитываются по дате окончания, без даты остаются отдельным списком. Даты просмотра сохраняются в `media`; новые переходы статуса могут заполнить их, чтение старых карточек не создаёт вымышленных дат. Время библиотек отображается отдельно от объединённых интервалов таймлайна.

JSON-копия версии 2 включает `media`. Импорт версии 1 поддерживается с пустой киноколлекцией; замена данных, валидация и восстановление выполняются одной транзакцией. Сброс очищает киноколлекцию вместе с остальными личными данными.

## Оформление

Базовый текст — 16 px, большинство подписей и контролов — 13–16 px, основной вес 400, кнопки 500, заголовки 600. Цвета фона, текста, границ и акцента заданы семантическими CSS-переменными. Светлая тема имеет собственные контрастные цвета, включая таймлайн, модальные окна, ошибки и настройки.

Выбор темы хранится в localStorage только этого браузера. Небольшой скрипт в `index.html` применяет сохранённую тему до первого рендера; при недоступном хранилище переключатель продолжает работать в текущей вкладке. Предпочтение оформления не смешивается с резервной копией личных записей.

Поиск и подписанные чекбоксы переиспользуют компоненты shared со scoped-стилями, чтобы стили обычных полей не меняли их раскладку. Модальные окна блокируют прокрутку фона и не используют размытие всей страницы. `scrollbar-gutter: stable` предотвращает сдвиг ширины при появлении полосы прокрутки; её цвета берутся из палитры темы.

## Карточки сводки

`pages/activity/ui/ActivityMetrics.vue` отображает основные показатели и выбранные категории. `MetricPicker.vue` переиспользует `CheckboxField`, управление фокусом и защиту от закрытия при выделении текста. Дополнительные карточки используют ту же сводку выбранного дня, недели или месяца, что и основные показатели.

Выбор и порядок категорий хранятся в таблице SQLite `dashboard_cards`, доступны через типизированный `/api/dashboard-cards` и входят в bootstrap и резервные копии. Удаление категории каскадно удаляет её карточку; старые копии восстанавливаются без дополнительных карточек. Валидация отклоняет неизвестные и повторяющиеся категории до изменения данных.
