# Архитектура Vue

Решение проверено по официальной документации **23 октября 2026 года**.

Проект использует Vue 3, Composition API и `<script setup>`, с декомпозицией по принципу **pages first из FSD 2.1**. Сначала выделяем самостоятельные экраны, затем выносим действительно общие сценарии и предметную логику. Не создаём пустые слои и по отдельному модулю для каждой кнопки.

## Структура

```text
src/
  app/
    App.vue                     # каркас, навигация, сборка моделей
    model/useWorkspace.js       # загрузка общей базы, диапазон дат, таймеры
    config/navigation.js
    styles/base.css             # размеры, сетки, компоненты
    styles/themes.css           # семантические цвета и светлая палитра
  pages/
    activity/                   # таймлайн и статистика общего периода
    games/                      # библиотека и локальная модель фильтров
    settings/                   # категории, оформление, резервные копии
  features/
    record-editor/              # редактирование, удаление, импорт и диалоги
    appearance/                 # смена и сохранение темы
  entities/
    activity/                   # объединение интервалов, аналитика, колонки таймлайна
    game/                       # статусы игр
  shared/
    api/client.js               # HTTP и единая обработка ответов
    lib/date.js                 # локальные даты и общая арифметика времени
    lib/format.js               # форматирование для UI
  main.js                       # точка входа
```

## Границы

Зависимости направлены вниз: `app → pages → features → entities → shared`. Можно пропускать слои. Страница не импортирует другую страницу, feature — другую feature. Внешние импорты срезов идут через `index.js`; детали реализации остаются внутри. Проверка `scripts/check-architecture.mjs` включена в `npm run check` и CI.

`App.vue` создаёт модели один раз. Страницы получают необходимые модели и действия явными props; не импортируют состояние из `app`. Модель редактирования получает зависимости аргументом. Это позволяет менять каркас приложения и проверять расчёты без браузера. Модели возвращают обычный объект refs, что сохраняет реактивность при деструктуризации; `reactive` применяется на границе передачи модели в UI.

Состояние фильтров принадлежит библиотеке игр. Состояние формы принадлежит редактору. Общее состояние таймеров и выбранного периода живёт в единственном экземпляре модели рабочего пространства. Интервалы и обработчики очищаются при размонтировании.

Pinia — официальная рекомендация Vue для более сложного управления общим состоянием. Здесь пока достаточно одного владельца состояния и composables, без глобальных singleton и дополнительных зависимостей. При появлении независимых маршрутов, нескольких владельцев состояния или необходимости DevTools stores можно заменить внутреннюю реализацию модели на Pinia, сохранив границы модулей. Vuex для нового кода не используется.

## Оформление

Базовый текст — 16 px, большинство подписей и контролов — 13–16 px, основной вес 400, кнопки 500, заголовки 600. Цвета фона, текста, границ и акцента заданы семантическими CSS-переменными. Светлая тема имеет собственные контрастные цвета, включая таймлайн, модальные окна, ошибки и настройки.

Выбор темы хранится в localStorage только этого браузера. Небольшой скрипт в `index.html` применяет сохранённую тему до первого рендера; при недоступном хранилище переключатель продолжает работать в текущей вкладке. Предпочтение оформления не смешивается с резервной копией личных записей.
