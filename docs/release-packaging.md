# Состав релизов

Пользовательский пакет и архив исходников решают разные задачи. Пользовательский ZIP запускает приложение; исходники содержат тесты, конфигурацию и инструменты разработки. GitHub отдельно формирует **Source code (zip/tar.gz)** из тега: наличие тестов в этих архивах нормально.

## Time & Games

В `TimeAndGames-X.Y.Z.zip` входят:

- готовый интерфейс `dist/`;
- сервер и его транзитивные локальные модули TypeScript/JSON;
- production-манифест, lockfile с зафиксированными зависимостями и скрипт запуска npm;
- Windows launcher, инструкция подключения и описание версии;
- `release.json` с версией и коммитом сборки.

Сервер выполняется средствами Node.js 24.12+, поэтому его `.ts`-модули являются файлами запуска. Исходники Vue, тесты, линтер, конфигурация сборки, devDependencies и кэш npm в пакет не входят. Версии зависимостей при сокращении lockfile не меняются.

Базы, WAL/SHM, резервные копии, `.env`, токены и профиль не копируются. При чистом запуске создаётся пустая база со стандартными категориями, без аватара и подключения к трекеру.

## Activity Tracker и Chrome

Эти пакеты выпускаются в [отдельном репозитории](https://github.com/GameModify/activity-tracker/releases).

| Пакет | Содержимое для работы |
| --- | --- |
| Windows installer / portable | Исполняемый файл, собранные модули сервиса и трея, интерфейс управления, иконки, необходимые нативные библиотеки и уведомления о сторонних лицензиях |
| Chrome ZIP | `manifest.json` в корне, JavaScript сборщиков и service worker, HTML/CSS интерфейса и необходимые ресурсы |

Нативные зависимости Windows нельзя удалять по одному признаку `node_modules`: они нужны сборщикам. Пользовательские данные хранятся вне каталога программы; настройки расширения находятся в хранилище Chrome.

Карты исходников `.js.map` необязательны для выполнения. В опубликованном расширении 0.8.0 они присутствуют и помогают диагностике; в последующих production-сборках их можно выпускать отдельно. Удаление карт должно согласовываться с настройками сборки и ссылками `sourceMappingURL`, включая копию расширения внутри Windows-пакета.

## Проверка перед публикацией

1. `npm run verify`: строгие типы, архитектура, линтер, форматирование, сборка и тесты.
2. `npm run package:release`: явный список файлов, сокращение production-lockfile, ZIP и SHA-256.
3. `npm run smoke:release`: распаковка в новую папку, проверка отсутствия файлов разработки и данных, запуск launcher, все маршруты интерфейса, пустое начальное состояние, сохранение профиля и повторный запуск без сети.
4. После загрузки: сверка опубликованного ZIP с контрольной суммой.

Исправление только упаковки уже опубликованной версии допустимо без изменения кода приложения и номера версии. При такой замене тег сохраняется, контрольная сумма обновляется вместе с ZIP, а коммит упаковки указан в `release.json`. Изменения поведения приложения требуют нового выпуска.

## Ориентиры

Состав и сборка сопоставлены 26 октября 2026 года с популярными самостоятельными приложениями:

- [Memos: Dockerfile](https://github.com/usememos/memos/blob/main/scripts/Dockerfile): отдельная стадия сборки; в конечный образ копируются готовый сервер и entrypoint.
- [Immich: Dockerfile](https://github.com/immich-app/immich/blob/main/server/Dockerfile): production-зависимости отделены от инструментов сборки; готовые сервер и веб-интерфейс копируются в конечный образ.
- [ActivityWatch: упаковка](https://github.com/ActivityWatch/activitywatch/blob/master/Makefile): готовые компоненты собираются в отдельный каталог, затем создаются установщики и архивы.
- [uBlock Origin Lite: Chromium/MV3](https://github.com/gorhill/uBlock/blob/master/tools/make-mv3.sh): отдельный каталог расширения, явное копирование ресурсов и лицензий, исключение журнала из ZIP.
- [Chrome: подготовка расширения](https://developer.chrome.com/docs/webstore/prepare): пакет содержит файлы расширения, манифест находится в корне ZIP.
- [GitHub: архивы исходников](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives): автоматические ZIP/tar.gz соответствуют снимку репозитория.

Это ориентиры для разделения разработки и исполнения; форматы Docker, PyInstaller и Chromium не переносятся между приложениями механически.
