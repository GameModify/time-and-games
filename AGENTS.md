# Работа над Time & Games

- Работай в текущем checkout. Соблюдай CONTRIBUTING.md: feature-ветки, Conventional Commits, PR и squash merge.
- Архитектура фронтенда описана в docs/architecture.md. Применяй pages-first: UI конкретного экрана остаётся в его срезе; общую логику выноси по мере реального повторного использования.
- Зависимости направлены app → pages → features → entities → shared. Не импортируй app из нижних слоёв и не делай cross-import между срезами одного слоя. Используй публичные index.ts.
- Весь новый код пиши на TypeScript, Vue-компоненты используй с `<script setup lang="ts">`. Сохраняй строгие проверки TypeScript и ESLint; не подавляй ошибки через `any`, `@ts-ignore`, `@ts-nocheck` или отключение правил. Внешние данные проверяй до использования.
- Каждая функция, метод и callback: максимум 20 строк (включая пустые строки, комментарии и сигнатуру), когнитивная сложность не выше 20. Ограничения действуют также в тестах и скриптах, исключения и отключения правил запрещены. Разделяй по смысловым операциям, не уплотняй строки ради лимита.
- Между модулями передавай типизированные модели и DTO. JSON разбирается и сериализуется только в адаптерах HTTP, SQLite и резервных копий; внешние данные проходят Zod-проверку.
- Предпочитай Vue Composition API, script setup и composables с явными зависимостями. Не возвращай новый монолитный App.vue.
- Интерфейс на русском, текст читаемый при масштабе 100%, обе темы должны сохранять контраст. Используй переменные палитры.
- Полные проверки запускай после завершённой задачи, перед коммитом/PR: npm run check, npm run build, npm test. Не запускай их после каждого микроизменения. Для UI также нужна проверка в доступном браузере; явно сообщай, если инструменты не имеют доступа к localhost.
- Не коммить SQLite, резервные копии пользователя, Steam API Key, .env, node_modules, dist и файлы .qa.
