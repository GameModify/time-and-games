# Vue: границы и состояние

Для Vue-приложений используй Composition API и pages-first из FSD 2.1, если проект не задаёт другую архитектуру.

- Направление зависимостей: `app → pages → features → entities → shared`, слои можно пропускать.
- UI отдельного экрана остаётся в `pages/<slice>`. Выноси сценарий в `features`, предметные модели и расчёты в `entities`, независимые компоненты и адаптеры в `shared` при реальной необходимости.
- Не делай cross-import между срезами одного слоя. Внешние потребители среза используют его публичный `index.ts`; внутренние файлы одного среза могут импортировать друг друга напрямую.
- `app` собирает модели и маршруты. Страницы получают нужные модели и действия явно; нижние слои не читают состояние из `app`.
- Composables получают явные зависимости и сохраняют refs при передаче потребителям. Назначай одного владельца каждому состоянию. При размонтировании очищай интервалы, подписки и обработчики.
- Классы не обязательны. Если локальный контроллер обоснован, его методы должны оставаться небольшими, контекст обработчиков сохраняться, а публичная модель — быть явной. Не заменяй длинный composable столь же монолитным классом ради формального лимита строк.
- Pinia уместна при нескольких независимых владельцах общего состояния и потребности в инструментах stores. Не добавляй её только ради наличия дополнительного слоя.
- Проверь фактические импорты и публичные API автоматическим инструментом, учитывая используемые расширения файлов и alias. Само наличие папок не доказывает соблюдение архитектуры.
- Переиспользуй поля, чекбоксы, поиск и рейтинг через существующие компоненты. Проверь русские подписи, обе темы, фокус, перенос текста и сохранение состояния после переходов/обновления страницы для затронутых сценариев.
